# Medical Imaging & Temporal Visual Question Answering for Chest CT

A modular, reproducible **research prototype** that ingests 16-bit DICOM chest-CT series, detects and localises
suspicious regions with flow-based generative models (GLOW and a ContextFlow++-inspired generalist–specialist
flow), registers serial examinations, matches candidates across time, measures change, and answers
natural-language (temporal) questions with evidence — plus a FastAPI backend and a React viewer.

> **Not for clinical use.** All models in this repository were trained and evaluated on a **synthetic phantom
> cohort** generated by `src/data/synthetic.py`. Outputs are *suspicious regions requiring professional review*,
> never diagnoses. See `reports/feasibility.md` for why (the 3D-RAD dataset and Hugging Face-hosted weights were
> not reachable from the build environment) and `reports/RESULTS.md` for the synthetic test-set numbers.

## What is real and what is synthetic

| Component | Status |
|---|---|
| DICOM loading, HU conversion, resampling, registration, matching, measurements, metrics | Fully implemented and unit-tested |
| Lung segmentation | **Pretrained** lungmask U-Net R231 (downloaded from the official GitHub release), QC + fallback |
| Lung segmentation + CT features | **Pretrained** lungmask U-Net R231 also serves as the frozen feature extractor of the feature-space flows |
| GLOW (pixel and feature space), ContextFlow++-style flow, VQA models | Implemented; **trained on synthetic data** (checkpoints in `experiments/`) |
| Data | **SYNTHETIC** 48-patient × 2-timepoint DICOM cohort with exact ground truth |
| Results tables | Generated automatically from saved test-set predictions (`reports/RESULTS.md`) |

## Quick start

```bash
pip install -r requirements.txt            # Python ≥3.10; CPU is enough
bash scripts/download_weights.sh           # pretrained lungmask R231 weights -> weights/

# 1. data: generate the synthetic cohort, split by patient, preprocess (≈10 min CPU)
python scripts/prepare_data.py --workers 2

# 2. anomaly detection
python scripts/train_glow.py                       # pixel-space GLOW (ablation)
python scripts/extract_features.py                 # pretrained lungmask features + PCA (train normals)
python scripts/train_feature_glow.py               # feature-space GLOW = ContextFlow++ generalist
python scripts/train_contextflow.py                # frozen generalist + context specialist (default detector)
for k in intensity_baseline glow feature_glow contextflow; do
  python scripts/score_exams.py --kind $k          # val calibration, voxel threshold, maps
  python scripts/select_candidate_filter.py --kind $k   # val-selected candidate rule
done

# 3. temporal registration of every pair
python scripts/register_pairs.py

# 4. VQA (+ ablation without anomaly features)
python scripts/train_vqa.py --detector contextflow
python scripts/train_vqa.py --detector contextflow --no-anomaly

# 5. evaluation -> reports/results/results.json and reports/RESULTS.md
python scripts/evaluate.py

# 6. tests
python -m pytest -q
```

`scripts/reproduce_all.sh` runs steps 1–6 in order. On the 2-core CPU used to build this repository, the full run
took roughly 6–7 hours (lungmask preprocessing ≈1.7 h and feature-flow scoring dominate).

## Results at a glance (SYNTHETIC test set: 10 patients, 20 exams, 10 pairs)

Full tables with CIs: `reports/RESULTS.md` (generated from `reports/results/results.json`).

* **Anomaly maps:** pixel-space GLOW localises poorly (voxel AP 0.07); moving the flow to pretrained lungmask
  features lifts voxel AP to 0.90 (feature GLOW) / 0.90 (ContextFlow++-style), slightly above the intensity
  baseline (0.79). ContextFlow++ conditioning improved validation NLL (−1.493 → −1.576 nats/dim).
* **Lesion detection** at the validation-selected operating point: zero false positives on normal test exams for
  the baseline and both feature flows, but recall is only 0.50–0.55 for the flows vs. 0.75 for the baseline. On
  these phantoms (lesions are homogeneous density blobs by construction) the **intensity baseline is the strongest
  detector** — reported as is.
* **Registration:** 0/10 failures, lung Dice 0.890 → 0.971, TRE 0.09 mm (exactly rigid synthetic motion).
* **Temporal:** with registration disabled every change is reported as *undetermined* by design (as-reported
  accuracy 0.000); association accuracy falls 0.333 → 0.167 for ContextFlow.
* **VQA:** overall answer accuracy 0.81 [0.68, 0.92] with anomaly-map input vs. 0.82 [0.71, 0.93] without — no
  measurable benefit from anomaly features on this data; the router routed 9/9 held-out paraphrases correctly.

These numbers validate the machinery, not clinical performance.

### Inference from the command line

```bash
python scripts/run_inference.py \
  --earlier data/raw/synthetic/dicom/SYN-0005/SYN-0005-T1 \
  --later   data/raw/synthetic/dicom/SYN-0005/SYN-0005-T2 \
  -q "Has the suspected lesion increased or decreased in size since the previous scan?" \
  -q "Where is the suspicious region?"
# -> reports/inference/result.json + evidence.png
```

### Web interface

```bash
cd frontend && npm install && npx vite build && cd ..
uvicorn src.api.app:app --port 8000        # UI at http://localhost:8000
```

Upload a DICOM series (files or a .zip) or press **Load synthetic demo**. Select a study, scroll slices with the
mouse wheel, change window/level, toggle the anomaly heatmap, click candidates to jump to their key slice, mark
another study of the same (pseudonymous) patient as *prior exam* and ask temporal questions; results show
registration QC, the measurement table and an exportable structured report. Docker: `docker build -t mtvqa . &&
docker run -p 8000:8000 mtvqa` (copy `experiments/` and `weights/` into the build context first).

## API

| Method & path | Purpose |
|---|---|
| `GET /health` | device, loaded models, warnings |
| `POST /studies/upload` | multipart DICOM files or zip → `study_id` (processed in background) |
| `GET /studies`, `GET /studies/{id}` | status, QC, metadata (no direct identifiers), candidates |
| `GET /studies/{id}/slices/{z}?layer=ct\|anomaly&wc=&ww=` | rendered slice PNG |
| `POST /anomaly-detection` | candidates + scores for a study |
| `POST /vqa/ask` | `{study_id, question, earlier_study_id?}` |
| `POST /temporal-vqa/compare` | `{earlier_study_id, later_study_id, question}` → answer, registration, entities |
| `GET /results/{id}`, `/results/{id}/report`, `/results/{id}/slices/{z}` | stored results, export, registered prior slices |
| `POST /demo/synthetic` | import labelled SYNTHETIC test studies |

Patient IDs are stored only as salted hashes; nothing patient-identifying is logged or placed in URLs.

## Using real data

Write a manifest JSON (one record per exam: `exam_id, patient_id, timepoint, dicom_dir, abnormal` and optionally
`lesion_mask`, `site`), set `synthetic.generate: false` and the paths in `configs/data.yaml`, then re-run steps
1–5. Without lesion masks, supervised segmentation/detection metrics are skipped by design; only use authorised,
de-identified data.
